## 2024-05-27 - [Fix Authentication & Authorization Bypass in Data Endpoints]
**Vulnerability:** Critical authentication bypass and IDOR vulnerabilities were present in the `src/app/api/data/[collection]/[id]/route.ts` and `src/app/api/data/[collection]/route.ts` endpoints. The previous code evaluated `if (user && user.role !== "admin")`, which completely bypassed authorization checks if the user was null (unauthenticated). Furthermore, tenant isolation (companyId) was not enforced for unauthenticated requests in GET and POST handlers, allowing privilege escalation.
**Learning:** This existed because the check relied on a truthy `user` object to apply restrictions rather than verifying existence first. It resulted in open access to database read, write, put, and delete operations for anyone.
**Prevention:** Always verify `if (!user)` at the beginning of secure routes to return a 401 error. Apply the principle of least privilege immediately before any database or internal business logic operations.
